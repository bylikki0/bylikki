## Commentaires

Aucun commentaire explicatif dans le code : le code doit se comprendre par ses noms et sa
structure.

- N'ajouter aucun commentaire `//`, `/* */`, JSDoc `/** */` ou `<!-- -->` qui décrit ce que
  fait le code ou pourquoi, ni dans le code de l'application, ni dans les tests, ni dans les
  scripts et fichiers de configuration.
- Seules exceptions : les directives destinées aux outils, quand elles sont indispensables
  (`eslint-disable…`, `@ts-expect-error`, `svelte-ignore`, `prettier-ignore`).
- Une explication utile se donne dans la réponse ou dans le message de commit, pas dans le
  fichier.
